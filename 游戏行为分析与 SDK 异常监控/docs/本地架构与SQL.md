# v0.8 本地技术架构与数据边界

## 目标与取舍

主要用途是让用户重新操作亲自做过或参与改造的功能，回忆业务、数据流和贡献；其次是面试演示。保留 v0.7 交互，新增可检查的本机 SQL 边界，而不是开发新的 SaaS。单进程、单用户、单机 SQLite，零第三方运行依赖。

历史参考是 Vue2/single-spa/SystemJS；当前仍是 native ESM/DOM/SVG。新的服务端、跨系统统一来源、SQL协议、自动导览和讲解卡都属于本次复现，不可当成当年公司的架构或用户历史交付。

## 入口和生命周期

`index.html → src/entry.js` 先并行读取 `/api/bootstrap` 与 `/api/datasets`。初始化 SQL 视图缓存和来自数据库的模拟数据快照，再加载 shell；后端不通则展示失败和重新连接，不退回内存伪装 SQL。

`src/shell/apps.js` 声明六个路由级模块，宿主序列化导航并忽略过期导航。首次 bootstrap，进入时 mount，同应用更新时 update，离开时 unmount。独立入口通过 `src/standalone.js` 加载同一个模块，不套整套主菜单。每个应用仍共用本地 origin、共享模块、样式和服务，不是强隔离沙箱。

`build:<name>` 构建该应用代码、共用依赖和独立 HTML/manifest；`build` 汇总全部。不需要为了微前端启动六个 Vite 服务，也没有偷偷把整个单文件塞进每个页面。只有自动演示使用 iframe 作临时工作区隔离。

## 两条真实路径

```text
查询：操作/URL → src/api → POST /api/query/*
    → 参数校验/绑定SQL → SQL结果 → 原domain/mapper → 页面状态/表格/图表

保存：编辑 → 同步视图缓存 → 待写队列
    → /api/workspace/commit → 预期键版本检查 → BEGIN IMMEDIATE
    → workspace_state + CRM/Report关系表映射 + 幂等回执 → COMMIT
    → ACK更新修订/清理队列 → UI显示已同步
```

独立事件预览会从配置生成模拟值；SDK配置预览用启动时读取的SQL计数样本展开，未采集字段标记缺失。SDK局部详情可从同一 SQL 快照计算，不是每次都远程请求。原业务样本是只读练习资料，本版没有提供编辑/删除样本记录的UI。

## Schema

| 表 | 用途 |
|---|---|
| behavior_records | 行为练习明细，日期/模块/设备/渠道/系统索引列及原记录JSON |
| sdk_samples | SDK计数行，事件/地区/日期/时间桶/平台/产品/设备/次数 |
| crm_activities | 已存活动结构化主字段与完整JSON |
| crm_prizes | 活动外键、产品组、奖品、概率、排序及完整JSON |
| report_fields | 通用字段，产品内别名唯一 |
| report_events | 事件配置，产品内别名唯一、修订号、字段树JSON |
| workspace_state | 兼容旧版键名的笔记/草稿/配置等；area+key主键、修订、删除墓碑 |
| workspace_meta | 工作区服务端全局修订 |
| committed_requests | 请求ID、内容哈希及同一事务提交回执 |
| seed_versions | 已应用种子版本；防止重启反复覆盖 |

严格表、JSON合法性、外键、索引、参数绑定；`PRAGMA user_version=1` 管理 schema。未来版本号高于程序则拒绝打开，不自行降级。初始化和种子均在事务中。WAL + synchronous FULL；一致性备份 `VACUUM INTO`。

保留复杂 JSON 是为了忠实维持字段树、模块独立状态与v0.7备份协议，不宣称所有配置完全范式化。关系表是同事务读模型，页面的编辑快照是兼容层；不要绕开仓储直接改一个表导致两者不同步。

## 幂等、并发和失败

每个提交含 requestId 和操作键 expected 修订。相同请求ID/相同内容返回旧回执，不再次执行；相同ID/不同内容拒绝。客户端在响应丢失时保留原请求，网络恢复后按相同ID重试。写入期间新输入保留自己的世代号，不被旧ACK清掉。

同键版本冲突返回409，整个事务不提交。相同值的重复写允许收敛。未发出/失败内容仍在视图缓存中，用户可导出；不偷偷强写。粒度是工作区键，例如整套CRM配置共用一个键，不是逐奖品协同编辑。没有多人权限、跨设备同步、后台任务队列或完整审计产品。

服务重启令牌轮换，已打开页面先导出待写内容再刷新。数据目录不可写、schema过新、事务验证失败、跨站请求都会明确失败。Node进程中SQL同步执行适合本地小型演示，不用于高并发服务器。

## 本机访问与安全边界

服务只监听 `127.0.0.1`，Host仅允许当前port的localhost或127.0.0.1；API拒绝跨站 Origin/Sec-Fetch-Site，POST需本进程随机令牌和JSON。只静态提供index/src/apps/manifest，数据文件与server源码不通过HTTP公开。无任意SQL执行接口。请求最大8MB。

这不是身份认证产品或加密数据库；同机具备文件权限的程序可读取SQLite。不要改成0.0.0.0公网部署；不要存入真实生产凭据和公司数据。`data/`在gitignore中。

## 自动演示

19站导览复制同一业务模块到标记过的srcdoc会话；`store.js`识别演示标记并使用全新内存，不访问SQL客户端。它只验证模拟业务，不往主SQL库写演示奖品/笔记。正常主工作区与它的“保存”含义不同，界面保留临时会话提示。

## 验证边界

Node/SQL/HTTP测试真实执行；包含新进程重开、事务回滚、请求重放与SQLite备份。注入浏览器旧业务150场景与19站导览是无SQL传输的回归证据。真正的localhost浏览器端在本环境被管理员策略阻止，必须由Codex在用户电脑完成；不能将二者合并说成全链路通过。
