# v0.6 自动串联演示

## 为什么这样做

已能操作页面，并不等于已理解它们的业务关系。导览将每一站的实际操作与业务目的、技术数据流、应记住的边界一起展示。不是继续增加后台页面，也不是录一段无法接管的动画。

## 自动路线

总览 → 事件基础 → 字段树 → 三套页面配置 → 实际配置预览 → 数据来源 → SDK 监控 → 选择窗口 → EBI 事件分析 → 设备明细 → 系统分组 → 分组弹窗 → 同设备单用户异常 → 技术调用 → CRM 活动 → 奖品 A/B 切换 → 概率超限阻断 → 修正保存重开 → 总结。

## 控制

首次点击入口自动播放；默认每站8秒，快速4秒，慢速16秒。执行和等待时间另计。暂停后可逐站前进，也可通过下拉选择回看；不是要求用户跟随固定日程。

回退、跳转、失败重试或手动接管后恢复自动：重建一个全新的临时实例，快速执行此前步骤，再停在指定站。恢复期间会遮住跳动的界面并显示进度，不假装瞬间回到了原状态。

真正的用户鼠标/键盘操作会接管；程序派发的点击不会误触发接管。Esc 暂停。关闭会取消当前操作和计时器；父工作区保持原状。不会把自动录下的步骤写进用户的历史贡献证据。

## 数据保护与架构

外部工作区保持挂载，但在模态导览打开时设为 inert；关闭后恢复，防止误操作背景。导览单独创建同源 srcdoc iframe，加载**同一份业务宿主模块**；store 模块在加载之初识别 data-replay-demo-session 标记，选择全新的内存仓储，不访问原生 localStorage/sessionStorage。

这里的 iframe 是演示隔离容器，不是声称公司原来用 iframe，也不代表整个业务工程已更换微前端方案。

source 入口沿用已有 script-src self 策略，iframe 不运行内联脚本、不开放远程代码；离线入口复用打包的 Blob ES 模块。实际 HTTP/file 入口仍需要在用户本机验收。

## 失败与导出

操作由条件等待和结果断言驱动，不是每隔几秒盲点坐标。找不到目标或数据核对不一致时停止，显示具体原因，可重试或接管。导出仅包含实际执行步骤的结果，未运行的步骤 result=null；不生成伪通过记录。

文字字幕没有语音。导览会话在退出/重建后丢弃；要保留自己在导览内部试改的配置，需要使用相应页面的导出，正式复盘笔记应回原工作区写。
