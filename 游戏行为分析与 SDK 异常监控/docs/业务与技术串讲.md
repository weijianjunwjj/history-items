# 业务与技术串讲 · 本次复现辅助

## 业务主线

“配置端先定义事件及字段，决定页面怎么展示和查询。监控端观察哪个时段发生异常，从时段带着事件、产品、平台进入分析；事件次数和设备数是两种口径。再进入设备列表，按维度分组，最后查看同一台设备的异常记录。”

这是帮助理解的本次演示主线，不声称复刻了原公司所有系统间协议。配置不生成真实数据，本地固定样本模拟采集边界。CRM另讲活动/奖品/规则的配置闭环，不假装它属于异常排查链。

## 技术主线

“宿主负责URL、页签和应用生命周期；业务应用拥有页面局部状态。跨页只传稳定标识与过滤范围，不把整个组件store互相共享。API层隔开数据读取与页面，转换层处理固定样本和heads/list响应。图表与表格来自同一过滤集合，所以能核对上报次数与去重设备数。”

打开技术页的最近一次getDevices或getModule，结合真实参数讲清职责；当前原生ESM代码不能当作历史Vue2工程。关于历史经验，只讲用户确认或原始记录支持的部分。

## 现场验证

SDK登录异常04:00—04:30为10台/25次；下钻分析应一致。再去设备/分组，点击SDK-DEMO-1-1002，应看到4条异常记录。六类正常行为没有对应来源，明确留空。不同产品、平台的数字以当前页面计算为准。
