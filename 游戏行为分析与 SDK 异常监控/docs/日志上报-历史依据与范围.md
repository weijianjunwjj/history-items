# EBI V3.27 日志上报：下一轮范围与原始记录定位

整理日期：2026-10-13。当前演示仍为 v0.2；本文件是遗漏模块核对与后续范围，不是 v0.3 已完成代码或验收记录。

## 结论与边界

用户在2026-01-05提供的年度总结明确提到“日志上报功能阶段（V3.27）”，称其为第一个相对完整模块，最终基本完成并正常使用。2025年9—10月的代码与排查记录则对应 reportEventManage 与 behaviorDesign 的字段、事件及页面配置。版本号来自总结；不能单凭每个代码片段证明最终上线状态和逐行原创。

现有 v0.2 的设备日志查询不等于这一版日志上报配置功能。下一轮重点是配置端，而非再增加一张日志表。

## 建议补齐的操作链

通用字段定义 → 上报事件基础配置 → 事件字段树 → 列表展示／查询条件／详情页配置 → 保存重开 → 用模拟数据验证配置效果。

配置效果预览是本次复现的验收辅助，不能在缺乏依据时声称原系统具有同样的一键预览入口。不接入真实采集SDK、公司接口和原动态页面平台。继续沿用已有演示工程，不在这一轮迁移技术栈。

## 应优先恢复的行为

- 三个配置区域状态独立；左侧字段加入右侧时不移走原字段。
- 不可查询字段由 supportQuery 规则拦截；同一区域避免重复加入。
- 拖拽排序与字段配置变更分开处理，避免 watch 覆盖排序或无关修改。
- 切换字段或配置标签前按既有规则校验，失败时不丢失当前编辑上下文。
- 保存后重开恢复顺序、显示名称及查询配置；变更检测按最终确认规则实现。
- 树使用递归数据结构，深度限制集中设置；10月20日的记录证明提出过动态层级改造，但不能单凭请求认定当年最终可支持任意深度。
