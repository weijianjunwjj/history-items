## 3. 本地执行顺序

1. 在项目根目录确认 `node -v`、可写目录、端口；保留现有数据库和用户修改。有data/replay.sqlite时先 `npm run db:backup`。不要删除或重置它来躲测试。
2. `npm run verify`。没有运行依赖，不需要npm install；Node必须22.16+。ExperimentalWarning本身非失败。产出命令、版本与结果。
3. `npm start`，打开 `http://127.0.0.1:4173`。验证六应用菜单、独立 `/apps/ebi/index.html`，跨应用生命周期，以及无JS/CSP/HTTP错误。
4. `npm run test:browser`。可选Python测试需Playwright，Windows脚本默认尝试Edge；必要时CHROMIUM_PATH指定已安装的Chromium系浏览器。不要绕管理员政策。测试自动用临时DB和随机端口，默认包含19站完整自动播放。
5. 手动验证下面的最小路径。自动脚本阻断时记录准确失败点、日志和截图，修源码后回归，不放宽断言冒充完成。

## 5. 优先排查点

- **HTTP CSP与srcdoc**：自动演示在真实HTTP下使用本地外部module入口，不应改宽CSP来掩盖路径错误。必须复用当前模块和演示内存隔离。
- **刷新恢复**：SQL初始化必须先于shell/API导入；否则模块会错误选中旧浏览器存储。
- **保存时序**：不要移除flushStorage/ACK。SQL状态为pending/error时不能说已保存。
- **服务重启令牌**：目前需刷新旧页面重新握手。有待写内容先导出；不要清空缓存作自动重连。
- **同库多窗**：版本冲突是保护机制；先导出和手动合并，不采用last-write-wins强盖。
- **Windows路径/端口**：脚本从自身目录启动；允许中文和空格；PORT可覆盖；数据库文件不依赖当前终端cwd。
- **可选Python测试**：`browser_local.py`未能在此环境完整执行，选择器/本机浏览器差异可能需修正。不要据已有注入测试就断定本地SQL UI通过。
